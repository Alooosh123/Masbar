# MISBAR — خطة اختبارات قبول الإنتاج\n\nهذه الاختبارات مطلوبة قبل إعلان MISBAR جاهزًا. نجاح CI أو تشغيل Backend لا يثبت نجاح API الحقيقي أو الأجهزة الميدانية.\n\n## 1. تسجيل Google\n- [ ] Client ID نفسه في Backend GOOGLE_CLIENT_ID وFrontend VITE_GOOGLE_CLIENT_ID.\n- [ ] Google Console origins تشمل رابط الإنتاج وlocalhost للتطوير.\n- [ ] ID Token يرفض عند audience غير مطابق أو email_verified ليس true.\n- [ ] أول بريد موثق ينشئ customer فقط؛ حسابات موجودة تحفظ أدوارها ولا تتم ترقية حساب.\n- [ ] حساب inactive يرفض.\n- [ ] Logout يحذف HttpOnly cookie.\n- [ ] password-login يرفض عند إعداد Google.\n\n## 2. الرؤية — اختبار API حقيقي\n- [ ] صورة معدة مدعومة واضحة مع لوحة البيانات.\n- [ ] معدة غير مدعومة، صورة ضبابية، حجم كبير، MIME غير صالح.\n- [ ] اختبار 402/403، 401، 429، 5xx، timeout، network error.\n- [ ] JSON غير صالح وconfidence خارج 0..1.\n- [ ] لا تنشأ جلسة إلا لمعدة ضمن القائمة المغلقة وثقة فوق الحد؛ تأكيد المستخدم مطلوب.\n- [ ] لا تسجل API keys أو tokens أو base64 للصور.\n\n## 3. RAG ومصادر OEM\n- [ ] استبعاد بيانات sample من الإجابات الفنية العملية.\n- [ ] كل خطوة/قيمة لها OEM source، صفحة PDF، رقم مستند، revision، model-code match.\n- [ ] اختبار العربية/الإنجليزية، أسماء طرازات وأرقام قطع exact match.\n- [ ] الامتناع عند غياب المصدر أو اختلاف الطراز/revision.\n- [ ] الاستشهادات صحيحة ومقتطف المصدر يدعم الادعاء.\n- [ ] Siemens S7-1200: تحديد CPU/version ثم إدخال System Manual الرسمي المناسب.\n- [ ] Caterpillar C15 ACERT: الحصول على Service/O&M manual عبر Cat أو موزع مرخص؛ لا نفترض صلاحية دليل عام لكل serial prefix.\n- [ ] التحقق من حقوق الاستخدام/التخزين قبل إدخال PDF.\n\n## 4. كاميرا وأجهزة حقيقية\n- [ ] Android Chrome وDesktop Chrome: permission، capture، retake، cancel، orientation، focus/lighting.\n- [ ] HTTPS شرط للكاميرا والميكروفون.\n- [ ] شبكة بطيئة، رفع كبير، request timeout.\n- [ ] منع جلسات مكررة في الطلب والتأكيد.\n- [ ] اختبار كاميرا فعلية (وليس canvas/CDP mock).\n- [ ] تجربة صورة معدة مدعومة حقيقية.\n\n## 5. أمن وتشغيل\n- [ ] تدوير مفاتيح OpenRouter وغيرها التي ظهرت سابقًا.\n- [ ] AUTH_REQUIRED=true وCORS origins محددة.\n- [ ] الأسرار لا تظهر في logs أو responses.\n- [ ] Rate limiting لتسجيل Google والرؤية.\n- [ ] Health readiness صحيح لكل مزود.\n- [ ] Logs آمنة ومهيكلة، لا raw provider error ولا صور/token.\n- [ ] اختبار Backup/Restore SQLite وليس backup فقط.\n- [ ] توثيق Sleep وCold start.\n\n## 6. شروط الإصدار\n- [ ] Backend tests، TypeScript/build، Docker smoke pass.\n- [ ] Google login حقيقي على نطاق الإنتاج.\n- [ ] API رؤية حقيقي لصورة مدعومة وغير مدعومة.\n- [ ] مصادر OEM واستشهادات راجعة.\n- [ ] اختبار كاميرا جهاز فعلي.\n- [ ] مراجعة PR #22 وPR #23 ثم الدمج بموافقة المالك.\n
