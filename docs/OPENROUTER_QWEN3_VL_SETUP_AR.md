# إعداد Qwen3-VL عبر OpenRouter API في MISBAR

## الهدف

استخدام نموذج الرؤية Qwen3-VL-8B-Instruct عن طريق API مستضاف. لا يتم تنزيل النموذج ولا تثبيت Ollama على جهاز المطور أو Backend.

## حساب OpenRouter ومفتاح API

1. أنشئ حسابًا في OpenRouter.
2. أنشئ API Key من لوحة المفاتيح.
3. خزّن المفتاح في متغير سري على الخادم باسم `OPENROUTER_API_KEY`.

لا تضع المفتاح في Git أو متغيرات واجهة React/Vite أو رسائل الدعم. يرسل Backend الطلبات فقط.

## إعداد Backend

أضف الإعدادات التالية إلى `.env` المحلي أو متغيرات Railway لخدمة Backend:

```env
VISION_PROVIDER=openrouter
OPENROUTER_API_KEY=<YOUR_OPENROUTER_API_KEY>
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
VISION_MODEL=qwen/qwen3-vl-8b-instruct
VISION_TIMEOUT_SECONDS=60
DEMO_MODE=false
```

لا حاجة لإضافة Ollama أو Qwen model files أو أي خدمة inference محلية.

### فصل الرؤية عن المحادثة

`VISION_PROVIDER` يتحكم في:
- تحديد الشركة/المعدة من صورة.
- تحديد القطعة بعد تأكيد نوع المعدة.

أما `CHAT_PROVIDER` فيتحكم في خدمة المحادثة العامة فقط. لا يلزم Cohere لمساري الرؤية أعلاه عند تفعيل OpenRouter. إن لم تتوفر خدمة محادثة، يمكن تعطيلها عبر:

```env
CHAT_PROVIDER=off
```

## واجهة API

يستخدم الموصل عنوان OpenRouter المتوافق مع OpenAI:

`POST https://openrouter.ai/api/v1/chat/completions`

ويرسل:
- `model=qwen/qwen3-vl-8b-instruct`
- صورة داخل رسالة متعددة الوسائط بصيغة `image_url` وData URL.
- تعليمات ومجموعة مغلقة من المعدات أو أرقام القطع المسموح بها.

يفحص Backend JSON الناتج ويتأكد أن المعدة أو القطعة موجودة في الكتالوج. النتيجة غير الصالحة أو غير المدعومة لا تُقبل. لا يتم اعتماد هوية المعدة قبل تأكيد المستخدم.

## التكلفة والحدود

Qwen3-VL-8B-Instruct عبر OpenRouter ليس مجانيًا في صفحة النموذج وقت إعداد هذا الدليل. السعر المدرج هو:
- 0.117 دولار لكل مليون رمز إدخال.
- 0.455 دولار لكل مليون رمز إخراج.

قد يتغير السعر أو مزودو الاستضافة وحدود الطلبات. راجع صفحة النموذج مباشرة: https://openrouter.ai/qwen/qwen3-vl-8b-instruct

توجد نماذج مجانية أخرى على OpenRouter، لكن معرف `openrouter/free` يختار نموذجًا مجانيًا مناسبًا ولا يضمن استخدام Qwen3-VL؛ لا تستخدمه في اختبار الدقة الثابت أو اعتماد قبول الإنتاج.

## خطة الاختبار

1. اختبار وجود إعداد API Key دون كشف قيمته في السجلات.
2. اختبار طلب صورة إلى OpenRouter من Backend.
3. تجربة صورة لكل معدة مدعومة ومراجعة اسم الطراز.
4. تجربة معدات غير مدعومة وصور غير واضحة.
5. التأكد من عدم قبول نتائج خارج الكتالوج.
6. التأكد من أن الحالة تبقى بانتظار التأكيد حتى موافقة الفني.
7. اختبار تحديد قطعة من قائمة القطع بعد تأكيد المعدة.

اختبارات CI تستخدم استجابات HTTP وهمية؛ لا تعد اختبار اتصال فعلي. لا تعلن نجاح الربط حتى تنجح تجربة API بمفتاح صالح وصورة حقيقية.

## الخصوصية

الصور سترسل من Backend إلى OpenRouter ومزود النموذج الذي تختاره الخدمة. راجع شروط الخصوصية والاحتفاظ لدى الخدمة قبل رفع صور معدات العملاء أو مواقعهم.
