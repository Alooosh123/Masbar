# MISBAR — قبول الفهم متعدد الوسائط والتشخيص دون صورة

هذه قائمة قبول للميزة الجديدة. الاختبارات الآلية لا تثبت نجاح الأجهزة الحقيقية أو مزود AI الحي.

## 1) الصور (كاميرا + معرض)
- [ ] Android: فتح الكاميرا، إذن/رفض الإذن، التقاط، معاينة، إعادة التقاط، إلغاء.
- [ ] Android: اختيار صورة موجودة من معرض/منتقي الملفات، معاينة، حذف/إعادة اختيار.
- [ ] Desktop: اختيار صورة من الملفات، التحقق من النوع والحجم، معاينة.
- [ ] PNG/JPEG/WebP صالحة، ورفض نوع غير صورة أو ملف أكبر من 5MB.
- [ ] صور لوحة بيانات واضحة/غير واضحة: عدم تخمين نص أو رقم.
- [ ] وصف العناصر المرئية، نوع المعدة المحتمل، OCR للنص/الموديل/serial/part number/rating والتحذيرات فقط إذا مقروءة.
- [ ] مستوى ثقة نوعي (مرتفع/متوسط/منخفض) مع ذكر حدود الرؤية، دون نسب مختلقة.
- [ ] إذا اسم المعدة مجهول: يكمل الوصف ولا يشترط الاسم.

## 2) النص والصوت مع الصورة
- [ ] إضافة شرح مكتوب للصورة ثم تحليلها مع الشرح.
- [ ] اختيار العربية أو الإنجليزية لتحويل الكلام إلى نص.
- [ ] بدء التسجيل وإيقافه؛ إظهار حالة التسجيل.
- [ ] تشغيل التسجيل وإعادة الاستماع، ثم حذف التسجيل.
- [ ] اختبار الإملاء الصوتي المباشر: عربي وإنجليزي، كلمات صناعية/أسماء طرازات، ضوضاء معتدلة، إذن/رفض الميكروفون.
- [ ] تأكد من أن نص الكلام المفرغ والشرح المكتوب والصورة يُستخدمون في نفس تحليل الصورة.
- [ ] التسجيل الصوتي الخام محليًا فقط ولا يُرفع؛ النص الناتج عن التعرف المباشر هو ما يُرسل للمساعد.

## 3) تشخيص حواري دون صورة أو معدة
- [ ] بدء المحادثة بوصف الأعراض من الذاكرة دون صورة أو اسم/موديل.
- [ ] المساعد يسأل سؤالًا توضيحيًا واحدًا في كل رد، ويتدرج في جمع الأعراض.
- [ ] عربي وإنجليزي.
- [ ] لا يختلق معدة/سبب/قيم أو إجراءات صيانة.
- [ ] لا يقدم عزمًا أو خطوات فك/تركيب أو توصيلات أو LOTO دون سياق ودليل OEM مطابق.
- [ ] يكتشف مؤشرات خطر (دخان/احتراق/حركة غير متوقعة/تسرب خطير) ويوقف التشخيص ويقدم تنبيه سلامة عام.
- [ ] بعد توفير صورة/معلومات، يحافظ على السياق ويذكر أن التشخيص الأولي غير مؤكد.

## 4) الأعطال والجودة
- [ ] API vision/chat: 401/402/403/429/5xx/timeout/network.
- [ ] JSON/مخرجات غير صالحة، OCR غير واضح، صورة فارغة/كبيرة.
- [ ] عدم إنشاء جلسة معدة مؤكدة من الوصف العام أو الصورة غير الواضحة.
- [ ] لا تسجل مفاتيح API أو Base64 أو بيانات صوت/صورة حساسة في السجلات.

## 5) الأجهزة الحقيقية والإصدار
- [ ] Android Chrome عبر HTTPS: كاميرا فعلية + معرض + ميكروفون + MediaRecorder + إعادة تشغيل.
- [ ] Desktop Chrome/Edge: الكاميرا/الميكروفون/منتقي الملفات.
- [ ] اختبارات CI: backend tests + TypeScript/build + Docker runtime smoke.
- [ ] لا دمج أو نشر قبل نجاح CI والاختبارات الميدانية ومراجعة النتائج.
