# سجل تقدم مِسبار

## 3.13 تجهيز النشر السحابي مع واجهة API من نفس النطاق

- تعديل API URL: في Vite development يستمر الاتصال المحلي على المنفذ 8010؛ في production تستخدم الواجهة نطاقها الحالي.
- نقل Nginx من ملف إعداد ثابت إلى قالب Runtime يستقبل `PORT` و`BACKEND_UPSTREAM`.
- إضافة تمرير داخلي لمسارات `/api/` و`/health` و`/ws/` عبر Nginx إلى Backend.
- جعل Backend يستمع على متغير `PORT` مع افتراضي 8000، وإبقاء فحص صحة Docker متوافقاً مع المنفذ.
- توسيع Docker Compose لتحديد `PORT` و`BACKEND_UPSTREAM` محلياً.
- توسيع CI لاختبار الصحة وقائمة المعدات عبر نطاق الواجهة نفسه، وإنشاء جلسة واستعادتها بعد إعادة تشغيل Backend عبر وسيط Nginx.
- إضافة دليل Railway بالعربية لخدمتين داخل مشروع واحد، مع إبقاء Backend على Private Networking.

**الحالة:** ملفات الإعداد ودليل النشر أضيفت على فرع `codex/misbar-cloud-preview-setup`. يلزم اجتياز CI ثم ربط Railway بحساب GitHub وإنشاء الخدمات والنطاقات. لم يتم حتى الآن إنشاء مشروع Railway أو نشر نسخة دائمة.

**القيود:** العرض يستخدم `VISION_PROVIDER=mock` و`CHAT_PROVIDER=off` ولا يحتوي على بيانات صيانة معتمدة أو مصادقة/RBAC. قاعدة SQLite تحتاج إلى Volume دائم مع التحقق من صلاحيات UID 10001 أو إلى ترحيل لقاعدة بيانات مشتركة قبل الاعتماد الإنتاجي.
