# تقرير التقدم — مسبار (Masbar)

**التاريخ:** 18–21 نوفمبر 2026
**الإصدار:** 0.2.0 (MVP محادثة + محرك سلامة + صوت عربي + سجل OEM)
**المستودع:** https://github.com/Alooosh123/Masbar

---

## 1. الملخص التنفيذي

تم بناء نسخة كاملة قابلة للتشغيل من المساعد الصناعي، ثم تحويلها إلى **مساعد محادثة عربي عام** (ChatGPT-style) يعمل بالكاميرا والصوت من داخل المحادثة، مع الحفاظ على محرك السلامة الصناعي الحتمي. يشمل ذلك خادم FastAPI، وقاعدة معرفة تجريبية (9 قطع / 3 معدات)، وواجهة React عربية RTL داكنة، وجلسات وسجل تدقيق، ومزوّد محادثة ورؤية حي (Cohere).

**النتيجة:** 64/64 اختبار pytest، و34/34 فحص E2E فعلي عبر Chrome، و12 لقطة موثّقة.

تم اختيار **المنفذ 8010** بدل 8000 لأن الأخير محجوز على الجهاز من خدمة Mizan Router (Docker/WSL). لا يوجد أي تداخل بين المشروعين.

### 2.3 قاعدة المعرفة

- `cat_c15_fuel_system.json` — Caterpillar C15 ACERT (3 قطع)
- `cat_320d_hydraulics.json` — Caterpillar 320D (3 قطع)

### 2.4 الواجهة (PWA — واجهة محادثة)

- React 18 + TypeScript + Vite.
- RTL كامل، وضع داكن عالي التباين، تصميم محادثة بفقاعات وردود سريعة.
- `ChatScreen` نقطة الدخول: رسالة ترحيب، شريط حالة الجلسة، بطاقات قطعة/سلامة/خطوة داخل المحادثة.
- `ChatCamera`: فتح/إغلاق بالأمر أو بالزر، معاينة حية، زرّا «التقاط ووصف» (افتراضي) و«التقاط وتحديد».
- الميكروفون وTTS: أزرار داخل المحادثة + أوامر «افتح الميكروفون»/«اقرأ».
- إعادة تعيين تأكيدات السلامة عند كل تحديد جديد عبر `identification_id`.
- PWA: manifest + service worker + أيقونة.

### 2.5 التشغيل والنشر

- سكربتات: `dev-backend.ps1`، `dev-web.ps1`، `test.ps1`، `smoke_api.ps1`، و`e2e_chat.py`.
- `Dockerfile` للخادم + `web/Dockerfile` (Nginx) + `docker-compose.yml`.

### 3.2 اختبار الدخان الحي (الخادم على 8010)

```
[PASS] Full safety-gated flow completed successfully.
```

النقاط المتحقق منها:

1. `/health` → online، 9 قطع، 3 معدات، `vision_provider=cohere`.
2. إنشاء جلسة → `CREATED`.
3. تحديد القطعة 312-5620 → `AWAITING_LOTO`.
4. محاولة خطوة قبل LOTO → **409 مرفوضة**.
5. تأكيد جزئي لـ LOTO → **409 مرفوضة**.
6. تأكيد كامل → `READY`.
7. الانتقال للخطوة 4 → عزم **45 N·m** من `SENR9834-08` صفحة 142.
8. سؤال «كم العزم؟» → إجابة 45 N·m مع المصدر والتنبيه.
9. سجل التدقيق يحتوي `component_identified`, `loto_confirmed`, `step_viewed`.
10. رقم قطعة غير معروف → **404 مرفوض**.

### 3.3 التحقق من الواجهة

- `npm.cmd install` اكتمل (71 حزمة) رغم خروج PowerShell بالرمز 1 بسبب تحذير `allowScripts` الخاص بـ esbuild؛ البناء يعمل.
- `npm.cmd run build` نجح: TypeScript بدون أخطاء + Vite أنتج الحزمة (180 KB JS / 33 KB CSS).
- تم اختبار التدفق الكامل في Chromium داخل التطبيق:
  - تحميل 3 معدات من الخادم وعرضها.
  - فتح جلسة C15 → تحديد تجريبي (ثقة 93%) → ظهور بوابة LOTO مقفلة.
  - تأكيد البنود الثلاثة → `READY` وظهور الخطوة 1.
  - التنقل إلى الخطوة 4 → بطاقة عزم 45 N·m مع المصدر ووسم «بيانات تجريبية».
  - سؤال «كم العزم؟» كتابةً → إجابة 45 N·m مع المصدر.
  - إنهاء الإجراء → حالة `مكتمل` وبطاقة إنجاز.
  - البحث اليدوي → 3 قطع، واختيار قطعة جديدة يعيد تعيين تأكيدات LOTO والخطوات (إثبات عزل الحالة).
  - عارض سجل التدقيق → 3 أحداث أولية (إنشاء، بدء تحديد، تحديد) مع أوقات عربية.
- الكاميرا مرفوضة في بيئة الاختبار (لا يوجد إذن)، ووضع «بلا كاميرا» يعمل كما هو مصمم.
- RTL مؤكد (`html dir=rtl`) ولا يوجد تجاوز أفقي (scrollWidth = clientWidth).

### 3.4 ملاحظات من الاختبار

- زر «إنهاء الإجراء» قد يقع خلف شريط الصوت الثابت عند منتصف التمرير؛ التمرير للنهاية يظهره. أضيف هامش سفلي 160px؛ يمكن تحسينه لاحقًا بإخفاء الشريط عند التمرير.
- لقطات الشاشة غير متاحة في بيئة الأتمتة الحالية (النافذة غير مرئية)، لذا تم التحقق عبر DOM والتزامن مع الـ API.

### 3.5 فحص مفاتيح API وتفعيل الرؤية الحقيقية

تم فحص ملف الاعتماد المقدَّم دون طباعة أي مفتاح. يحتوي الملف على خمسة أسطر اعتماد بلا أسماء مزوّدين أو عناوين:

| # | الشكل | النتيجة |
| --- | --- | --- |
| 1 | مفتاح Cohere قديم الطراز (40 حرفًا) | صالح |
| 2 | مفتاح OpenRouter (`sk-or-v1-...`) | صالح، لكن الرصيد غير كافٍ: النماذج المدفوعة ترجع HTTP 402 والمجانية ترجع HTTP 429 |
| 3 | UUID | غير موسوم؛ لم يُرسل إلى أي خدمة ولم يُخمّن مزوّده |
| 4 | مفتاح Groq (`gsk_...`) | صالح، لكن قائمة النماذج المتاحة للحساب لا تتضمن نموذج رؤية |
| 5 | مفتاح Cohere جديد (`cohere_...`) | صالح |

القرار: استخدام **Cohere Command A Vision** لأنه المزوّد الوحيد المتاح الذي يجمع بين مفتاح صالح ونموذج رؤية وحصة قابلة للاستخدام. تم وضع المفتاح في `.env` فقط، وضبط:

```env
VISION_PROVIDER=cohere
COHERE_BASE_URL=https://api.cohere.com/v2
VISION_MODEL=command-a-vision-07-2025
```

التنفيذ:

- إضافة `CohereVisionAdapter` يستخدم Chat v2 الأصلي مع **JSON Schema صارم**.
- تمرير قائمة المرشحين فقط؛ أي رقم قطعة خارج القائمة يُرفض في الخادم.
- رفض استجابة JSON غير صالحة أو ثقة منخفضة، دون تخمين.
- إصلاح تصنيف مصدر التحديد كي تُسجّل نتائج Cohere كـ `VISION_VLM` بدل `VISION_MOCK`.
- إضافة ثلاث اختبارات لاختيار المزوّد والتحقق من الإعدادات.
- عدم إرسال أي مفتاح إلى الواجهة أو السجلات.

التحقق الحي:

- `GET /health` يعيد `vision_provider: "cohere"`.
- صورة اصطناعية تحمل الرقم `312-5620` أُرسلت إلى `/identify`.
- النتيجة: `312-5620`، الثقة `1.0`، المصدر `VISION_VLM`، والحالة `AWAITING_LOTO`.
- صورة لا تحمل قطعة معروفة (`UNKNOWN`) رُفضت: لا `identified_component`، بقيت الجلسة `CREATED`، وظهر طلب إعادة المسح بدل التخمين.
- `38 passed` آنذاك (ارتفع العدد لاحقًا إلى 51 بعد إضافة اختبارات المحادثة)، واختبار الدخان الكامل `PASS`.

ملاحظة: الصورة المستخدمة اصطناعية لاختبار المسار البصري والتحقق من الالتزام بقائمة المرشحين، وليست صورة قطعة حقيقية. ما زال يلزم اختبار صور ميدانية فعلية وضبط حد الثقة قبل الاعتماد التشغيلي.

### 3.7 الصوت العربي وربط مصادر OEM (21 نوفمبر 2026)

**الصوت:**

- أُضيف `EdgeTtsAdapter` يستخدم الأصوات العصبية العربية فقط، والافتراضي `ar-SA-ZariyahNeural`.
- نقاط جديدة: `POST /api/v1/tts` و`GET /api/v1/tts/voices` (8 أصوات عربية).
- الخادم يرفض أي صوت غير عربي ويعيد 503 بدل تمرير نص عربي إلى صوت إنجليزي.
- أُضيفت **ذاكرة MP3 دائمة** في `data/cache/tts/`: العبارات المتكررة تُنطق حتى عند تعذر خدمة Edge.

- أُضيف زر **«اختبار الصوت العربي»** في ترويسة المحادثة، وزر إعادة النطق لكل رد.
- الردود الطويلة (مثل قائمة 31 شركة) تُقسَّم إلى مقاطع عربية متتابعة بدل إرسالها في طلب واحد يتجاوز الحد.

## 4. قرارات معمارية

1. **واجهة محادثة أولًا:** كل شيء يُدار من المحادثة (كاميرا، صوت، جلسة، LOTO، خطوات، عزم)، مع أزرار مباشرة تُظهر نفس الإجراءات.
2. **محرك سلامة حتمي:** لا توليد LLM لأي نص حرج (خطوات، عزم، LOTO). الـ VLM والـ LLM يقترحان/يصفان فقط، والقيم النهائية من `data/kb/`.
3. **الجلسة على الخادم:** الواجهة لا تستطيع تجاوز LOTO حتى لو عُدّلت، ولا تستطيع أوامر المحادثة تجاوزها أيضًا.
4. **فصل الوصف عن التحديد:** الصور تُوصف افتراضيًا ولا تغيّر القطعة؛ التحديد يتطلب وضع `identify` صريحًا.
5. **قاعدة معرفة JSON قابلة للاستبدال:** مخطط واضح + تحقق عند الإقلاع.
6. **مزوّد قابل للتعطيل:** `CHAT_PROVIDER=off` و`VISION_PROVIDER=mock` يبقيان مسارًا يعمل دون مفاتيح.

## 6. الخطوات التالية

1. اختبار VLM على صور قطع حقيقية (لا صور اصطناعية) وضبط حد الثقة حسب النتائج.
2. اختبار الكاميرا والميكروفون على جهاز ميداني حقيقي عبر HTTPS، بما يشمل التعرف الصوتي العربي بكلام حقيقي وTTS مسموع.
3. تحسين تجربة المحادثة على الشاشات القصيرة (تمرير أذكى، إخفاء الشريط عند الكتابة).
4. إضافة فهرسة متجهات وNeo4j عند الانتقال لمقياس أكبر من 9 قطع.
5. استبدال البيانات التجريبية بأدلة مصنّع رسمية مع سير عمل اعتماد فني.
6. تجربة PWA على هاتف عبر HTTPS (كاميرا + ميكروفون).
