# سجل تقدم مِسبار

## 3.10 بوابة اعتماد موثقة لبيانات قاعدة المعرفة وضبط CORS (21 نوفمبر 2026)

**ما أضيف على فرع التطوير:**

- أصبح ضبط ملف المعدة إلى `data_status=verified` يتطلب `equipment_verification_evidence`، ومطابقة الموديل، ونطاق مراجعة الهوية.
- أصبح ضبط القطعة إلى `verification_status=verified` يتطلب `verification_evidence` مطابقاً لمعرف الدليل والصفحة والموديل.
- يجب تسجيل SHA-256 للمصدر، رقم الوثيقة ومراجعتها، مرجع لوحة بيانات داخلي، نطاقات المراجعة، وقتين مزودين بمنطقة زمنية، ومعرفي مراجع/معتمد مختلفين.
- لا يمكن اعتماد قيم العزم دون مراجعة نطاق `torque`؛ ولا يمكن اعتماد سجل ذي LOTO/تحذيرات دون مراجعة نطاق `safety`.
- حُدّث `SafetyGuard` حتى لا يعتبر مجرد تغيير حقول الحالة اعتماداً للعزم، وحتى يعيد `source_status=sample` عندما تفشل بوابة الدليل.
- تمت إضافة اختبارات رفض البيانات التي تفتقد دليلاً أو تخالف الصفحة/الموديل/نطاقات المراجعة.
- تم منع wildcard CORS في بيئة الإنتاج، مع تغيير الإعداد الافتراضي في Docker Compose إلى أصل محلي محدد بدلاً من `*`.

**الحدود:** تحقق التطبيق من اتساق بيانات الدليل المسجلة، لكنه لا يثبت وحده أصالة PDF أو مطابقة SHA-256 للملف الأصلي، ولا يثبت كفاءة المراجع أو صحة المعلومة الفنية. لا توجد حالياً بيانات صيانة فعلية مرقاة إلى verified؛ تظل بيانات المشروع الحالية sample.
