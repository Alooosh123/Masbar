# النسخ الاحتياطي واستعادة SQLite في مِسبار

## ما الذي توفره هذه الأداة؟

يوفر الملف backend/app/ops/sqlite_backup.py أداة نسخ احتياطي متسقة لقاعدة SQLite التي تحتوي بيانات المستخدمين والجلسات وسجل التدقيق.

تستخدم الأداة واجهة SQLite الرسمية Connection.backup() لالتقاط قاعدة البيانات أثناء وجودها في وضع WAL، ثم:

1. تنشئ الملف المؤقت داخل مجلد النسخ الاحتياطي نفسه.
2. تفحص النسخة باستخدام PRAGMA integrity_check.
3. تحسب SHA-256 وتسجل الحجم والجداول ووقت الإنشاء في ملف Manifest.
4. تنقل الملف المؤقت إلى الاسم النهائي بعد نجاح الفحص.
5. تحذف فقط النسخ القديمة التي تطابق نمط اسم هذه الأداة، وفق مدة الاحتفاظ المحددة.

## إنشاء نسخة احتياطية

من مجلد backend أو من داخل حاوية Backend:

python -m app.ops.sqlite_backup

الإعدادات الافتراضية:

- قاعدة البيانات: SESSION_DB_PATH أو /app/data/sessions/sessions.sqlite3.
- مجلد النسخ: SQLITE_BACKUP_DIR أو /app/data/sessions/backups.
- الاحتفاظ: SQLITE_BACKUP_RETENTION_DAYS أو 14 يومًا.

يمكن تمرير مسارات مختلفة:

python -m app.ops.sqlite_backup --database /path/to/sessions.sqlite3 --destination /path/to/backups --retention-days 14

تطبع الأداة JSON يحتوي على المسار والحجم وSHA-256 وحالة سلامة SQLite، ولا تطبع محتويات المستخدمين أو كلمات المرور أو الجلسات.

## اختبار الاستعادة

1. انسخ ملف .sqlite3 إلى مسار استعادة منفصل.
2. افتحه باستخدام SQLite أو نفّذ PRAGMA integrity_check.
3. تحقق من وجود جدولي auth_users وsessions وسجل التدقيق.
4. لا تستبدل قاعدة الإنتاج مباشرة أثناء تشغيل الخدمة.
5. عند الاستعادة الإنتاجية: أوقف الخدمة أولًا، احتفظ بنسخة من الحالة الحالية، ثم استبدل ملف قاعدة البيانات فقط وفق إجراء تغيير موثق، وأعد الخدمة وتحقق من تسجيل الدخول والجلسات.

## حدود مهمة قبل الاعتماد

مجلد النسخ الافتراضي يقع داخل Volume نفسه المركب على /app/data/sessions. هذا يحمي من تلف الملف المنفرد أو خطأ تشغيلي، لكنه **ليس نسخة خارجية**؛ فقدان Volume أو حذفه قد يؤدي إلى فقد الأصل والنسخ معًا.

للحماية من فقدان Volume نحتاج إلى تخزين كائنات خارجي S3-compatible أو خدمة نسخ احتياطي مستقلة، مع مفاتيح محفوظة كأسرار، وجدولة، واختبار استعادة دوري. لا تُفعّل خدمة تخزين خارجية أو تنشئ موردًا مدفوعًا دون مراجعة التكلفة أولًا.

## لقطة تلقائية عند بدء الخادم

يمكن تفعيل إنشاء لقطة عند كل بدء للحاوية عبر متغيرات Backend التالية:

- SQLITE_BACKUP_ON_STARTUP=true
- SQLITE_BACKUP_DIR=/app/data/sessions/backups
- SQLITE_BACKUP_RETENTION_DAYS=14

عند تفعيل ذلك، ينشئ Backend لقطة متسقة بعد تهيئة قاعدة البيانات، ويتحقق منها ثم يحذف النسخ المعروفة التي تجاوزت مدة الاحتفاظ. فشل النسخ يسجل خطأ ولا يمنع تشغيل التطبيق أو يغير قاعدة البيانات الأصلية.

مهم: Railway مضبوط حاليًا على Sleep عند عدم وجود طلبات. لذلك لقطة بدء التشغيل تحدث عند بدء/إيقاظ الحاوية أو إعادة نشرها، وليست جدولة يومية مضمونة. ضمان وقت يومي ثابت يتطلب Cron خارجيًا يوقظ Backend أو إبقاء الخدمة نشطة، وقد يؤثر الخيار الثاني على التكلفة. كما أن اللقطات ما زالت داخل Volume نفسه وليست نسخة خارجية.
